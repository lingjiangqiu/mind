# 产品取舍与 HR 展示素材

## 这轮可核对的增量

原校园助手已经有意图、记忆、检索、风险判断、后台记录和工具队列。通用架构名不能作为差异化证据。

这轮把原来独立的哲学翻译能力放进一条可验证的学生体验：

1. 从一段泛化安慰，变为“感受—理解—在意的价值—可控选择—小行动—追问”的内部契约。
2. 学生读自然段；【】、小标题、哲学流派名不进入正文。结构用于产品校验与回归。
3. 六类视角有适用与禁用情境。欺凌优先边界/求助，哀伤优先陪伴，高风险完全跳过哲学。
4. 模型异常、截断或不合规输出回退到主题预设，并明确标注来源。
5. 从四个固定输入扩展到有上限的临时多轮体验，访客可直接试、查看本轮步骤，不要求留下真实咨询记录。

## 如何和公开项目比较

2026-11-11 阅读的公开资料：

- [CampusMind-Agent](https://github.com/vnsjvn/CampusMind-Agent)：README 包含 LangGraph 六节点、RAG、记忆、MCP、报告/通知，与本项目基础架构有大量相同概念。
- [Aegis Psych Agent](https://github.com/m4rklee/aegis-psych-agent)：README 强调风险协作、黑板/任务产物、管理端审计等。
- [MindBridge Campus Care Agent](https://github.com/OUAO-FRANK/mindbridge-campus-care-agent)：README 强调事件协作、混合检索、风险和后台；说明原始聊天的持久化边界。

这些是对公开文档的对照，不是对方全部代码的审计。不能据此断言它们“没有安全”“没有创新”或本项目效果更好。可以强调的方向差别是：把学生自己的情绪表达与选择支持作为主体验，并给出该体验的适用边界、失败回退、临时多轮和处理过程证据。

## 可以用于面试的 60 秒表述

> 我把校园助手的重点落在了学生日常困扰的表达整理上。通用安慰容易结束对话，所以我把之前的哲学翻译能力融入咨询路径：先接住感受，再看清在意的价值、能控制的事和一个可尝试的小行动。内部采用结构化输出，但学生看到自然聊天；对欺凌和哀伤限制视角，高风险跳过哲学。为了让招聘方能直接验证，我做了临时多轮体验和实际处理过程展示，并测试会话隔离、隐私、限流、兜底和无后台写入。当前验证的是工程行为；是否更有帮助，还需要用户研究和对照评估。

涉及“我做了”的内容，需要本人能解释产品决策、展示改动，并如实说明 AI 辅助实现。若基础来自课程或他人代码，应改成“在某基础上做产品迭代”，补来源，不把基础能力全部归为自己从零设计。

## HR 追问与证据

| 追问 | 可以展示的证据 | 当前限制 |
| --- | --- | --- |
| 为什么要加哲学？ | 同一句考试困扰的具体价值、可控事项、小行动和追问；`philosophy.py` | 产品假设，不是疗效结论 |
| 是不是只加了提示词？ | 条件节点、视角约束、结构校验、fallback、对抗测试 | 仍使用通用大模型，没有训练专用模型 |
| 是 Agent 吗？ | LangGraph 状态、分支与实际步骤 | 是受控工作流，不是自主规划或自主 MCP 调用 |
| 不适合用哲学的时候呢？ | 危机示例跳过哲学，欺凌/哀伤限制视角 | 词表和模型仍会漏报/误报，不提供危机服务 |
| 多轮怎么验证？ | 首轮讲考试，次轮只回答“是怕让家人失望”，检查实际承接 | mock 只验证路由，语义效果需要真实模型及用户评测 |
| 优点怎么量化？ | 结构完整率、不适用视角率、兜底率、耗时、动作可执行性评分 | 当前没有真实用户效果数字；不得编造提升百分比 |

下一轮建议先做小规模访谈/可用性测试，比较“泛化安慰”和“哲学整理”两种回复的相关性、自然度、被理解感和行动清晰度；预先约定评分标准，单独报告模型兜底率和中位/高分位耗时。
